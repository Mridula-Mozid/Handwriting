# Data, Folder, and CSV Guide

This project works as a small research pipeline, and each folder has a specific job. The raw handwriting images start in the dataset folder. From there, the code creates cleaned images, then feature tables, then model outputs, and finally explanation images. The point of this file is to make the data flow easy to follow for anyone reading the project, including someone who is not familiar with the code.

The raw source data is now organized under `D:\Final Semester\Thesis Work\Codes\Dataset\Spiral_Handwriting` with three dataset roots: `Public_Dataset`, `HandPD\Spiral_HandPD`, and `BD_Dataset`. Each dataset root has class folders `healthy` and `parkinson` or their dataset-specific equivalents. Public files use the `HP`/`PP` naming scheme, BD files are renamed to `BHP###_hand_spiral_01` and `BPP###_hand_spiral_01`, and HandPD files are standardized to `HPHP###_hand_spiral_##` or `HPPD###_hand_spiral_##` so patient IDs stay grouped correctly.

After preprocessing, cleaned images are stored in `preprocessed_images/<dataset>`. This folder is created by `preprocessing.py --output-base ...` for each dataset separately. Each dataset folder contains three parts. The `grayscale` folder holds the cleaned grayscale images used by deep learning. The `binary` folder holds cleaned binary masks used by handcrafted feature extraction. The `quality_check` folder stores side-by-side visual checks. The file `metadata.csv` is saved per dataset and is the main tracking file for that dataset pipeline.

The `metadata.csv` file is created by `preprocessing.py` for each dataset. It tells the next scripts where each image is stored, which class it belongs to, and which patient it came from. The compatibility columns remain `filename`, `patient_id`, `class`, `gray_path`, `binary_path`, `height`, and `width`, and the standardized subject-level fields now include `dataset_name`, `subject_id`, `class_label`, `image_path`, `processed_path`, `sample_index`, `original_filename`, and `master_patient_id`. This file is the bridge between raw images and the rest of each dataset pipeline. Both `feature_extraction.py --dataset <name>` and `train.py --dataset <name>` read it.

The `handcrafted_features_classical_ml` folder is created by `feature_extraction.py`. It now stores outputs under `handcrafted_features_classical_ml/Public_Dataset`, `handcrafted_features_classical_ml/BD_Dataset`, and `handcrafted_features_classical_ml/HandPD`. Each subfolder contains `handcrafted_features.npy`, `class_labels.npy`, `patient_identifiers.npy`, and `handcrafted_features_table.csv`.

The `deep_learning_results` folder is created by `train.py`. It now stores per-dataset outputs in `deep_learning_results/Public_Dataset`, `deep_learning_results/BD_Dataset`, and `deep_learning_results/HandPD`. Each subfolder includes `fold_1_predictions.csv` through `fold_5_predictions.csv` and `final_cross_validation_results.csv`.

The `trained_models_checkpoints` folder is also created by `train.py`. It stores saved ResNet-18 checkpoints per dataset in `trained_models_checkpoints/Public_Dataset`, `trained_models_checkpoints/BD_Dataset`, and `trained_models_checkpoints/HandPD` with files `resnet18_fold_1.pth` through `resnet18_fold_5.pth`.

The `classical_ml_results` folder is created by `H_ML_pipeline.py`. It now stores per-dataset outputs in `classical_ml_results/Public_Dataset`, `classical_ml_results/BD_Dataset`, and `classical_ml_results/HandPD`. Each subfolder contains `classical_ml_results.csv` and confusion matrix images per model and fold.

The `model_interpretability_visualizations` folder is created by `H_grad_cam.py`. It now stores per-dataset outputs in `model_interpretability_visualizations/Public_Dataset`, `model_interpretability_visualizations/BD_Dataset`, and `model_interpretability_visualizations/HandPD`. It contains Grad-CAM overlays and preview panels for sampled healthy and Parkinson images.

The main README files in the code folder explain each stage in more detail. `README_PREPROCESSING.md` describes how the raw images are cleaned. `README_FEATURE_EXTRACTION.md` explains the handcrafted features. `README_DEEP_LEARNING.md` explains the ResNet-18 training setup. `README_CLASSICAL_ML.md` explains the baseline machine learning models. `README_INTERPRETABILITY.md` explains the Grad-CAM output. The top-level `README.md` gives the full project story in one place.

If you want the short version, the flow is simple. Raw images from each dataset go into preprocessing. Preprocessing creates clean images and dataset-specific metadata. Metadata feeds feature extraction and deep learning for that dataset. Feature extraction creates the tables for classical ML. Training creates checkpoints and fold predictions. Classical ML creates baseline results. Grad-CAM uses the trained checkpoint to explain the deep model. Finally, `compare_datasets_results.py` creates `results/dataset_comparison_summary.csv` and `Visualization/09_Public_vs_BD_Performance_Comparison`.

This is the current data organization of the project, and this is how each file connects to the next one.
