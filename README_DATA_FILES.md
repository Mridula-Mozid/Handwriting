# Data, Folder, and CSV Guide

This project works as a small research pipeline, and each folder has a specific job. The raw handwriting images start in the dataset folder. From there, the code creates cleaned images, then feature tables, then model outputs, and finally explanation images. The point of this file is to make the data flow easy to follow for anyone reading the project, including someone who is not familiar with the code.

The raw source data is the handwriting spiral dataset stored outside the code folder in `D:\Final Semester\Thesis Work\Handwriting Dataset\workingData\drawings\spiral\All`. Inside that folder there are two class folders, `Healthy` and `Parkinson`. These are the original images before any cleaning or renaming. The file names now follow the research pattern you asked for. Healthy samples use the `HP` prefix and Parkinson samples use the `PP` prefix. The naming format is like `HP001_hand_spiral_01.png` or `PP014_hand_spiral_03.png`. These names help the code extract patient identity correctly and keep patient-level splitting safe.

After preprocessing, the cleaned images are stored in `preprocessed_images`. This folder is created by `preprocessing.py`. It contains three parts. The `grayscale` folder holds the cleaned grayscale images that are used by the deep learning model. The `binary` folder holds the cleaned binary masks that are used for handcrafted feature extraction. The `quality_check` folder stores side-by-side visual checks so you can inspect whether preprocessing preserved the handwriting properly. The file `metadata.csv` is also stored here. It is the main tracking file for the whole pipeline.

The `metadata.csv` file is created by `preprocessing.py`. It tells the next scripts where each image is stored, which class it belongs to, and which patient it came from. Its columns are `filename`, `patient_id`, `class`, `gray_path`, `binary_path`, `height`, and `width`. This file is the bridge between raw images and the rest of the pipeline. Both `feature_extraction.py` and `train.py` read it. That is why this CSV is one of the most important files in the whole project.

The `handcrafted_features_classical_ml` folder is created by `feature_extraction.py`. It contains `handcrafted_features.npy`, `class_labels.npy`, `patient_identifiers.npy`, and `handcrafted_features_table.csv`. The `.npy` files store the numerical arrays used by machine learning code. `handcrafted_features.npy` holds the feature matrix, `class_labels.npy` holds the target labels, and `patient_identifiers.npy` holds the patient IDs used for grouped cross-validation. The `handcrafted_features_table.csv` file is the readable version of the same information. It is useful when you want to inspect the extracted values in a spreadsheet or present them in a paper appendix.

The `deep_learning_results` folder is created by `train.py`. It stores the fold-wise prediction files from the ResNet-18 training run. The current files are `fold_1_predictions.csv` through `fold_5_predictions.csv`. Each of these files records the patient ID, the true label, the predicted label, and the predicted probability for the Parkinson class. These files are useful because they let you see what the model did in each fold, not just the final average score. They are also useful when you want to analyze errors or build a results table for your thesis or paper.

The `trained_models_checkpoints` folder is also created by `train.py`. It stores the saved ResNet-18 checkpoints for each fold. In the current run, the folder contains `resnet18_fold_1.pth` through `resnet18_fold_5.pth`. These are the learned model weights. They are required later if you want to generate Grad-CAM explanations or if you want to continue training or evaluate a specific fold again.

The `classical_ml_results` folder is created by `H_ML_pipeline.py`. It contains `classical_ml_results.csv` and the confusion matrix images for each model and fold. The CSV is the summary table with accuracy, precision, sensitivity, specificity, F1-score, and ROC-AUC. The confusion matrix images show the mistakes made by SVM, Random Forest, and XGBoost in each fold. This folder is the classical machine learning baseline output and is used to compare traditional models with the deep learning model.

The `model_interpretability_visualizations` folder is created by `H_grad_cam.py`. It stores the Grad-CAM images and preview images. The filename format includes the class name and the image name, such as `healthy_HP001_hand_spiral_02_gradcam.png`. These images are the explanation outputs. They show where the model looked while making a decision. This is important because it helps you show that the model is learning stroke-related patterns rather than random background details.

The main README files in the code folder explain each stage in more detail. `README_PREPROCESSING.md` describes how the raw images are cleaned. `README_FEATURE_EXTRACTION.md` explains the handcrafted features. `README_DEEP_LEARNING.md` explains the ResNet-18 training setup. `README_CLASSICAL_ML.md` explains the baseline machine learning models. `README_INTERPRETABILITY.md` explains the Grad-CAM output. The top-level `README.md` gives the full project story in one place.

If you want the short version, the flow is simple. Raw images go into preprocessing. Preprocessing creates clean images and metadata. Metadata feeds feature extraction and deep learning. Feature extraction creates the tables for classical ML. Training creates checkpoints and fold predictions. Classical ML creates comparison results. Grad-CAM uses the trained checkpoint to explain the deep model.

This is the current data organization of the project, and this is how each file connects to the next one.
